# 账号独立客户端环境

每个 OpenAI OAuth 账号持有一份 `extra.openai_codex_client_profile`，其中包含环境快照及独立的安装、设备 UUID。模板可重复使用，身份标识不共用。请求期间不重新抽取模板。

## 环境池

第一版提供 16 套相近的 Windows 环境：

| 字段 | 取值 |
| --- | --- |
| 系统构建 | Windows `10.0.26100` / `10.0.26200` |
| 架构 | `x86_64` |
| 屏幕与缩放组合 | 1920×1080 / 1；2560×1440 / 1；2560×1440 / 1.25；3840×2160 / 1.5 |

| Chromium / OTel SDK | `153.0.0.0` / `0.31.0` |

两个系统构建对应 Windows 11 24H2 / 25H2，见 [Microsoft 发布记录](https://learn.microsoft.com/en-us/windows-insider/release-notes/release-preview-24h2-25h2/build-26100-9267-26200-9267)。其余环境组合是生成的兼容性模板，并非 16 台真实设备的抓包记录。运行时与 SDK 版本沿用同一次抓包组合，不随机拼接版本。

## 分配与持久化

- 新建账号在写入数据库前分配模板并保存完整快照，安装 ID、设备 ID 为独立的 UUIDv4。
- 导入另一个账号的完整 JSON 时，环境可保留，身份 UUID 会重新生成。
- 复制账号丢弃原账号环境，再从池中分配；与复制操作原有幂等机制兼容。
- SQL 迁移 `193` 为已有 OAuth 账号分配环境，保留原先按账号派生的安装 ID，并发送调度缓存刷新事件。重复执行不会改变已经分配的环境。
- 普通编辑即使提交 `extra: {}`，仍保留客户端环境。账号更新可调整环境字段，但安装及设备 ID 不允许被其他账号的 ID 覆盖；禁止批量复制整个环境对象。
- 数据库更新入口在行锁内读取并保留当前客户端环境，覆盖 CRS 等外部同步整体替换 `extra` 的路径；跨账号复制身份会被拒绝。
- OAuth token 刷新、代理切换和进程重启不会重新分配环境。应用会话 ID 仍按账号在每次进程启动时独立生成，符合其会话生命周期。

## 请求与遥测

HTTP Responses、compact、WebSocket 握手及帧元数据、模型清单、后台测试/用量请求和 Desktop 辅助请求读取所选账号的环境；WebView 的语言与请求环境保持一致。

遥测按账号、代理、TLS 配置和环境快照分批。`app.version`、`service.version`、`os`、`os_version`、SDK 版本及 exporter UA 来自相应快照。更改环境不会把旧批次的资源字段改成新环境。

官方抓包中的 OTLP metrics 没有设备或安装 ID，因此没有向官方 metrics 额外添加这些字段，也不发送 OAuth Token 或 Cookie。两个账号使用同一模板时，部分环境字段相同是预期行为；各自请求数据和发送批次仍独立。代理相同也可能共用出口。
