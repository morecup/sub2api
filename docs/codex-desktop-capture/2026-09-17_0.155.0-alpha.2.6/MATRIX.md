# Work 模型与场景覆盖矩阵

这是独立桌面抓包副本中，通过 Computer Use 实际执行的本地 Work 项目测试。不是普通 Chat 测试，也不将自动标题或预热算作用户任务覆盖。

每格分别测试：首轮文本、同模型连续请求、图片附件、本地读取、新建文件、命令执行、预期命令失败后继续、手动压缩、压缩后修改文件、可见正文中断、中断后续接。

命令失败证据来自实际工具输出中的非零退出码及错误标记，不从提示词或脚本源码推定。部分模型捕获 Python 子进程的退出码 7 后令外层脚本返回 0；因此分别保存 `deliberate_child_exit_codes` 和 `deliberate_tool_exit_codes`，不将子命令失败等同于工具 API 整体失败。

HTTP 路径由本地抓包代理对仅该端点的 WS 握手注入 426 后触发，属于受控回退测试，不代表服务器自然返回 426。每格确认 HTTP POST 后移除注入。WS 格不注入。

## 本轮复核结果

五个模型 × WS/HTTP 的 10 组核心流程均完成。共增加 155 条 Work 模型请求：主任务 140 条（含 5 次 WS 预热）以及另计的 15 条标题请求。主任务中 130 条有正常完成事件，10 条是本次主动中断；10 条恢复请求均正常完成并返回预期标记。整个采集会话累计 202 条 Work 模型请求，首轮和 W01–W03 快照仍分别保留。

10 份输出 JSON 均由本地验证脚本独立复核，且压缩后的 `after_compact=true` 全部落盘。验证脚本实际输出 `MATRIX_VERIFIED` 的回传也逐组确认。最终 HTTP 回退开关已移除。

- Sol、Astra、Terra、Luna 的两条传输均有 Lite 标记；GPT-5.5 的两条传输均无 Lite 标记。所有本轮主任务请求实际推理强度为 `low`。
- 125 条普通主任务请求均为 `workspace_kind=project`，其中 96 条带非空 `workspaces`，29 条省略该键。不要把是否携带目录明细当作是否属于本地 Work 的唯一判据；本次没有定位省略的内部触发原因。
- Lite 的完成事件可能不附完整正文，恢复判定同时检查正文结束事件中的预期回复标记。
- 工具结果可能是 JSON 封装或带退出状态的纯文本，解析两种格式后再统计命令失败及验证输出。

补测后共观察到 81 个 OTLP 指标名，比旧样本多观察到 15 个；其中新增观察的 MCP 三项与 rollout 大小共 4 项在旧程序中已存在。15 项均归属 Rust `codex-app-server`。其中 9 项旧二进制未检出同名字符串的结论不变。详见 [遥测复核证据](matrix-telemetry.json)。

## 范围与仍需单列的维度

上述核心矩阵采用轻度推理、默认速度、请求批准的本地项目权限。它不是所有设置与所有功能的笛卡尔积覆盖。以下维度不能由核心矩阵推定通过：

- 各档推理强度、快速模式、权限模式切换。
- 多文件、非图片附件、空文件、大文件、复杂或超长工具结果。
- 并发工具、子代理、远程/云工作区、工作树、Git 远程、跨项目任务。
- 网络断线重连、代理超时、429/5xx、登录过期、服务端拒绝、工具审批拒绝。
- 音频、视频、搜索、连接器、插件、浏览器/电脑操作、定时任务。

原始抓包、TLS 密钥与本地路径均仅留在被 Git 忽略的私有抓包目录。此报告及 [matrix-evidence.json](matrix-evidence.json) 只输出白名单字段。

本表仅对以上 10 组核心流程作完成结论；上述扩展维度仍未全面测试。
