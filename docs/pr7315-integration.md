## 第一轮 OAuth 构造函数复核

再次以合并前的 `98690cf41582b588af970394158b22b38887f7af` 为基线，运行同一份合成输入对照程序，比较真实构造函数的输出，而不只比较画像文件。复核发现并修复了三处合并交互：

- 路由头新增的 `;tier=priority/flex/ultrafast` 被原遥测当成模型名的一部分，导致已知模型被归类为 `other`。HTTP 请求、SSE、WS 初始身份以及 WS→HTTP 回退现在统一只提取模型名；其余遥测结构不变。
- Messages→GPT 的中立构造阶段被补入 `x-codex-beta-features` 和 `x-codex-routing-hint`。已阻止普通 Responses 的补注逻辑覆盖该阶段；此处检查不能代表最终发出的身份头。完整入口仍有后置处理，下一轮审计进一步发现并修复了该处理的偏差。
- Live 创建及 sideband 的 OAuth 客户端身份被改为 Desktop 画像。已恢复该独立协议原先的 `codex_cli_rs/0.144.1` 身份；这不改变普通 Responses 的 `0.155.0-alpha.2.6` Desktop 画像。

本轮用户明确批准保留路由头例外：指定服务档位时，保留官方路由头的 `tier`，修复遥测解析。[OpenAI 官方变更 #37345](https://github.com/openai/codex/pull/37345) 明确将模型及选定的服务档位用于 HTTP、压缩请求和 WS 握手。现有 224 条官方 Desktop 模型抓包均未指定 `service_tier`，因此不能据此判断 Fast/Flex 的完整行为。

## 第二轮完整入口与传输复核（2026-09-18 至 19）

继续对照合并前 `98690cf4`，将检查点推进到完整转发函数实际调用上游的位置，并用本机 WebSocket、TLS 和 HTTP/2 服务验证后台读循环与传输工厂。本轮额外修正四类偏差：

1. **Messages 最终身份恢复。** 原版构造函数先清除身份头，但 `ForwardAsAnthropic` 在发送前重新配对 UA/originator，并恢复 `version: 0.144.1` 和 `OpenAI-Beta: responses=experimental`。前一轮只检查构造阶段，漏掉这一层。现在按原版恢复最终身份，保留浏览器 UA 兜底，不套用上游的统一版本改写；该入口仍不额外补入普通 Responses 的 beta-features/routing-hint。
2. **图片 Responses 的 Beta 头。** 上游在画像构造后又加入 `OpenAI-Beta: responses=experimental`，原版该路径没有此头。现已恢复其缺省状态。新 direct 图片协议保持自己的处理；用户确认图片主控模型采用 `gpt-5.6-luna`，模型相关的路由、Lite 标记和遥测标签允许相应改变。
3. **WebSocket 遥测记录边界。** 上游连接池常驻读取提前记录预取事件，把空闲等待算入读耗时，并在后台主动关闭空闲连接时生成 `read_error`。现在后台负责保活及排队，前台实际消费消息时才记录事件和等待时间；前台读超时记录一次错误，单纯空闲关连接不记录模型读错误。新增本机连接测试先复现失败，再验证修复，两项测试各连续运行 50 次通过。
4. **WebView 所继承的底层指纹。** 画像头部文件未变，但 `CreatePrivacyReqClient` 经共用工厂把 Chrome TLS/HTTP2 改为了 Firefox，影响额度、订阅、隐私和 Desktop 管理请求。已恢复原 Chrome 工厂，并固定 req/v3 升级改动的默认 `Accept`。同一份本机 TLS/HTTP2 测试在合并前版本通过、修复前版本失败、修复后通过；两版抓取的密码套件、曲线、签名算法、ALPN、HTTP/2 SETTINGS、窗口、优先级及解码后的有序请求头完全一致（去掉 TLS GREASE 随机值并固定本机地址）。Claude 使用独立工厂，仍采用已批准的上游实现。
