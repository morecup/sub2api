## 合并后 OAuth 行为复核

再次以合并前的 `98690cf41582b588af970394158b22b38887f7af` 为基线，运行同一份合成输入对照程序，比较真实构造函数的输出，而不只比较画像文件。复核发现并修复了三处合并交互：

- 路由头新增的 `;tier=priority/flex/ultrafast` 被原遥测当成模型名的一部分，导致已知模型被归类为 `other`。HTTP 请求、SSE、WS 初始身份以及 WS→HTTP 回退现在统一只提取模型名；其余遥测结构不变。
- Messages→GPT 的中立兼容入口被补入 `x-codex-beta-features` 和 `x-codex-routing-hint`。已恢复合并前的头部行为，避免普通 Responses 的补注逻辑覆盖该入口。
- Live 创建及 sideband 的 OAuth 客户端身份被改为 Desktop 画像。已恢复该独立协议原先的 `codex_cli_rs/0.144.1` 身份；这不改变普通 Responses 的 `0.155.0-alpha.2.6` Desktop 画像。

用户明确批准保留一项例外：指定服务档位时，保留官方路由头的 `tier`，修复遥测解析。[OpenAI 官方变更 #37345](https://github.com/openai/codex/pull/37345) 明确将模型及选定的服务档位用于 HTTP、压缩请求和 WS 握手。现有 224 条官方 Desktop 模型抓包均未指定 `service_tier`，因此不能据此判断 Fast/Flex 的完整行为。

对照覆盖 16 种持久化画像和旧账号回退画像，7 个模型，普通/priority/flex/ultrafast 档位，HTTP、透传、compact、WS、Messages、Live、模型清单、WebView、遥测导出，以及 Grok 推理和控制面的身份头。共 290 组输出：206 组完全一致，84 组只存在上述已批准的路由头 `tier` 差异；遥测内容无差异。比较前固定测试用进程随机 app-session UUID 与测量时间，WS 墙钟时间和 Live 随机 UUID 在验证类型后归一化。所有凭据、身份和请求均为合成测试数据。

上述对照针对已有普通 OAuth 流量，未开启新打票或传输插件，不涵盖其他凭据类型和 FedRAMP 认证扩展。该结果验证了所列输入下的请求头、解压后请求体及遥测字段和归属，不等于所有网络时序不变。上游的连接池保活、错误重试、缓存和新增功能仍会影响真实连接、请求次数及实际测量值。新打票采集和显式启用的传输插件属于额外出站流程；本次未向真实上游发送这些测试请求，也未重新抓取真实账号流量，不能据此保证不会触发上游风控。
